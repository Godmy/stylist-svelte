# AGENTS.md — перевод на русский

## ADR-001 - Политика адресного пространства морфологического ящика (обязательно)

- Эти правила распространяются на `stylist-svelte/modules/<module>/<domain>/**`.
- Каталог `src/lib` зонтичного репозитория содержит сгенерированные точки входа.
- Каталоги вида `.../<domain>/...` рассматриваются как предметные домены.
- Каталоги вида `.../<cluster>/...` рассматриваются как строгая типизация на уровне языка TypeScript и Svelte.
- Каталоги вида `.../<joint>/...` рассматриваются как строгая логическая типизация сущностей:
- `interface` - содержит шаблон сборки доменно-специфичных интерфейсов DSIAP.
- `function` - содержит названия чистых функций согласно функциональной таксономии.
- `class` - содержит названия паттерна проектирования, отражающее роль класса.
- `component` - содержит названия структурных элементов атомного дизайна.
- Каталоги вида `.../<family>/...` рассматриваются как основное семейство сущностей, например `canvas` или `theme`.
- Каталоги вида `.../<family-trait>/...` рассматриваются как уточнение основного семейства, например `canvas-axis` или `theme-mode`.
- Каталоги вида `.../<family-trait-trait>/...` рассматриваются как более детальное уточнение, например `canvas-axis-x` или `theme-mode-light`.

## ADR-002 - Политика содержательной кластеризации доменов и их логических звеньев (обязательно)

Содержимое кластера должно соответствовать его названию:

| Кластер     | Разрешённое содержимое                     | Допустимые логические звенья в кластере                             |
| ----------- | ------------------------------------------ | ------------------------------------------------------------------- |
| `const`     | Только `export const`                      | `value`, `map`, `record`, `preset`, `array`, `object`               |
| ----------- | ------------------------------------------ | ------------------------------------------------------------------- |
| `type`      | Только `export type`                       | `alias`, `record`, `struct`, `preset`, `object`, `compute`          | 
| ----------- | ------------------------------------------ | ------------------------------------------------------------------- |
| `interface` | Только `export interface`                  | `behavior`, `slot`, `recipe`, `contract`, `rest`, `graphql`         |   
| ----------- | ------------------------------------------ | ------------------------------------------------------------------- |
| `class`     | Только `export class`                      | `factory`, `facade`, `adapter`, `builder`, `repository`, `manager`, |
|             |                                            | `strategy`, `registry`, `visitor`, `...`                            |
| ----------- | ------------------------------------------ | ------------------------------------------------------------------- |
| `function`  | Только `export function`                   | `script`, `create`, `merge`, `resolve`, `serialize`, `transform`,   |
|             |                                            | `hook`, `check`, `state`, `test`, `capture`, `count`,               |
|             |                                            | `async`, `async-get`, `async-post`, `...`                           |
| ----------- | ------------------------------------------ | ------------------------------------------------------------------- |
| `component` | Компоненты Svelte, файлы state и stories   | `atom`, `molecule`, `organism`, `template`, `page`                  | 
| ----------- | ------------------------------------------ | ------------------------------------------------------------------- |
| `data`      | Специализированные вспомогательные данные  | `json`, `jsonl`, `md`, `yaml`, `icon`, `flag`, `png`, `shader`      |
| ----------- | ------------------------------------------ | ------------------------------------------------------------------- |
| `test`      | Наборы тестов Vitest для домена;           | ничего не экспортируют и никогда не реэкспортируются                |  

## ADR-003 - Политика структуры файлов и именования (обязательно)

В каталогах вида `.../component/<joint>/<family>/` разрешены только следующие файлы:
- `index.ts`
- `index.svelte`
- Необязательный `state.svelte.ts` - агрегатор реактивность компонента Svelte
- Необязательный `index.story.ts` — контракт story (`ContractStory` из `html/interface/contract/story`; элементы управления — `SlotStoryControl` из `html/interface/slot/story-control`). Описывает компонент, аргументы, элементы управления, предустановки и содержимое `HtmlNode`, типизированное через recipe компонента.
- Необязательный `index.story.svelte` — при наличии рядом `index.story.ts` используется исключительно для пользовательского рендеринга этой story и получает аргументы через props. Если существует отдельно, считается устаревшим форматом story.
- Необязательный `readme.md`.

В каталогах `state` разрешены только `index.svelte.ts` и `index.ts`.

В каталогах `test` разрешены только `index.test.ts` и `index.ts`.

В каталогах `data` разрешены только файлы следующих форматов:
```
*.frag, 
*.vert
*.json
*.jsonl
*.svg
*.png
*.md
```

Во всех остальных каталогах разрешён только один файл `index.ts`.

В любом каталоге допускается файл `README.md`, документирующий назначение, сущности по звеньям и потоки данных.

Диаграммы должны размещаться непосредственно в этих README в блоках `mermaid`, а не в отдельных файлах `.mmd`.

Для каталогов звеньев и семейств сохраняются перечисленные выше ограничения на файлы. Сами сущности документируются с помощью JSDoc.

## Политика направления сборки (обязательно)

Сохраняйте следующее направление композиции:

- Кластер `test` может импортировать любой кластер своего домена. Ни один другой кластер не может импортировать `test`.
- Кластер `class` может импортировать `function`: класс вправе вызывать функции своего домена. Сохраняйте существующие классы как классы — не переписывайте их в функции исключительно ради соблюдения направления.
- Не создавайте зависимости, нарушающие это направление, без явного согласия пользователя.
- Внутри `interface/` для DSIAP действует дополнительное одностороннее направление:

```
behavior / slot / contract (необязательный)
                  ↓
                recipe
```

Обратные зависимости запрещены.

### ADR-004 - DSIAP: шаблон сборки доменно-специфичных интерфейсов (обязательно для `.../interface/...`)

Кластер `interface/` следует целевой модели звеньев:

- `behavior` — атомарная поведенческая возможность (например, `BehaviorClickable`, `BehaviorFocusable`).
- `slot` — атомарная поверхность для контента или данных (например, `SlotLabel`, `SlotIcon`).
- `recipe` — композиция интерфейса компонента, собираемая из behaviors, slots и необязательных contracts.

### ADR-005 - Интеграция с внешними системами (обязательно для `.../interface/...`)

Кластер `interface/` может содержать импортируемую информацию из внешних систем:
- Каталоги `contract`, `rest`, `graphql` могут содержать в себе не обязательный третий этап после `recipe`.
- Он используется только тогда, когда необходимо отдельное соглашение на границе взаимодействия.
- `contract` — используется при необходимости отдельного соглашения на границе системы или между системами.
- `rest` — используется при необходимости отдельного соглашения для протокола REST.
- `graphql` — используется при необходимости отдельного соглашения для протокола GraphQL.

## Политика горячей перезагрузки рабочего пространства

- Перегенерация `dist` может нарушить или рассинхронизировать горячую перезагрузку.
- Запрещается запускать `yarn package`, `yarn build`, `svelte-package` или любые команды, пересоздающие `stylist-svelte/dist`.
- Разрешено выполнять перечисленные команды по указанию пользователя в текущем запросе.
- При неисправности рабочего пространства требуется перезапуск серверов.

## Модульное владение исходным кодом (обязательно)

- Владельцы исходного кода определяются в `modules.json`. Общие модули являются Git-подмодулями в каталоге `modules/`. Модули `booking`, `admin` и `travel` представляют собой отдельные приватные пакеты с одним доменом, кластеры которых находятся в корнях соответствующих репозиториев.
- Домены, включённые в карту модулей, размещаются исключительно в `modules/<module>/<domain>`. Не создавайте повторно ссылки или копии исходного кода в `src/lib` зонтичного репозитория. Скрипт `scripts/prepare-module-sources.mjs` проверяет рабочие копии и предоставляет физические алиасы без записи в файловую систему.
- Изменяйте файлы и выполняйте операции Git в физическом репозитории, которому принадлежит исходный код. `design-system` содержит вложенные репозитории `theme`, `svg`, `typography` и `layout`; `sandbox` содержит репозиторий `server`. Сохраняйте историю этих репозиториев.
- Архитектура «домен / кластер / звено / семейство» применяется внутри корня каждого модуля. Группировка модулей отражает принадлежность репозитория, а не дополнительный уровень доменной иерархии. `geo` и `wbd` — независимые вложенные репозитории по путям `modules/global/geo` и `modules/business/wbd`. Модуль `business` также включает `booking`, `admin`, `travel`, `spanish`, `sakartvelo` и `farm`. `prototype` — приватный контейнер, включающий `presentation` (репозиторий `stylist-svelte-prezi`) и `scratch`; всё внутри него является приватным.
- SvelteKit/Vite разрешают логические импорты доменов через `moduleAliases`; исключайте дублирование Svelte. Зеркала исходного кода читают фактические репозитории-владельцы доменов и исключают метаданные `.git`. При упаковке собирается игнорируемый каталог `.package-input`, а преобразование применяется только к скопированной сгенерированной точке входа. Никогда не редактируйте исходные агрегирующие файлы экспорта вручную.
- Публичный npm-пакет не должен включать `booking`, `admin` и `travel`. В публичной библиотеке запрещены зависимости исходного кода от этих приватных пакетов. Отдельные приватные пакеты импортируют общие сущности через подпути пакета `stylist-svelte`, а собственные или другие приватные сущности — через явно указанные подпути соответствующих пакетов. См. раздел «Политика логических импортов».
- Исключения для метаданных встроенных доменов также распространяются на `typography` и `layout`, зарегистрированные в `.gitmodules` репозитория-владельца `design-system`. Проверяйте `.gitmodules` конкретного модуля, а не только зонтичного репозитория.
- Сгенерированные корневые экспорты, включая корневые точки входа `booking`, `admin` и `travel`, по-прежнему могут генерироваться только человеком. После изменений сообщите Дмитрию, что необходимо выполнить `yarn stylist:manifest` из корня сайта. Никогда не запускайте глобальную генерацию самостоятельно.


## Политика логических импортов (обязательно)

- В написанном вручную исходном коде доменов внутри `modules/**` используйте логические абсолютные спецификаторы модулей для импортов и реэкспортов, включая stories, тесты, динамические импорты с литеральными путями и типы `import()`. Это правило распространяется и на зависимости внутри одной папки, например `./index.svelte` и `./state.svelte`.
- Общие домены рабочего пространства используют формат `$stylist/<domain>/<cluster>/<joint>/<family>`. При необходимости сохраняйте явно указанные имена файлов и расширения, например `$stylist/button/component/atom/button/index.svelte`.
- Отдельные пакеты (`stylist-svelte-booking`, `stylist-svelte-admin`, `stylist-svelte-travel`, `stylist-svelte-sakartvelo`) используют внутри себя подпути собственного пакета, например `stylist-svelte-travel/type/object/booking-quote/index.js`. Общие зависимости используют `stylist-svelte/<domain>/...`; приватные зависимости — имя пакета-владельца и должны соответствовать его контракту peer-зависимостей. Не добавляйте алиасы `$stylist` в исходный код отдельных пакетов.
- Перед заменой относительного пути убедитесь, что логический спецификатор разрешается в тот же физический файл во всех поддерживаемых окружениях. При необходимости зарегистрируйте алиасы пакетов и исходные пути TypeScript. Сохраняйте суффиксы query/hash.
- Сгенерированные агрегирующие файлы экспорта остаются под управлением генератора и могут использовать относительные реэкспорты. Не редактируйте их вручную ради соблюдения этой политики. Инфраструктура вне доменных кластеров (Node-скрипты, файлы пакетов и конфигураций) может использовать относительные пути.
- Пути файловой системы, URL ресурсов и вычисляемые пути времени выполнения не являются спецификаторами модулей. Не переписывайте их механически. Если у зависимости нет поддерживаемого логического адреса, сохраните работающий относительный импорт и сообщите об исключении.

- Тесты, импортирующие `component`, должны находиться в `<domain>/test/render/<family>/`. Звено `function/test` по-прежнему разрешено только для тестов, не импортирующих компоненты.
- Для проверки фактического использования звеньев запустите:

```
node "D:\2026\cloudflare\stylist-svelte-tools\scripts\reader.mjs" pipeline
```

Изучите файл `D:\2026\cloudflare\stylist\di\output\step-16-joints.md`. Раздел `Unknown Joints` перечисляет звенья, не разрешённые для соответствующих кластеров. Для работы reader требуется Node.js версии 24.11 или выше. Он читает существующий снимок индексации, включая физические модульные исходники.



## Исключение для встроенных репозиториев доменов-подмодулей (обязательно)

- Домены, зарегистрированные как Git-подмодули в `.gitmodules` репозитория-владельца, рассматриваются как границы встроенных репозиториев.
- Домены `theme`, `svg`, `typography` и `layout` принадлежат `design-system`; `server` принадлежит `sandbox`; `wbd` зарегистрирован в `business`, а `geo` — в `global`. Кроме того, `business` регистрирует `booking`, `admin`, `travel`, `spanish`, `sakartvelo` и `farm`, а `prototype` — `presentation` и `scratch`.
- В корне каждого такого домена, помимо обычной структуры, разрешены файлы `.git`, `LICENSE` и `README.md`. Это метаданные, привнесённые подмодулем, а не нарушение архитектуры.
- Исключение действует исключительно в корне встроенного репозитория и только для доменов, действительно перечисленных в `.gitmodules` соответствующего владельца.
- Весь исходный код внутри встроенного репозитория должен по-прежнему соответствовать правилам доменов, кластеров, звеньев, семейств и сборки, если отдельным правилом явно не предусмотрено иное.


## Правила изменения исходного кода (обязательно)

- Каждый файл исходного кода должен экспортировать ровно одну сущность.
- Сохраняйте строгую типизацию сущностей на уровне языка и логической структуры.
- Не создавайте файлы с несколькими экспортируемыми сущностями.
- Не оставляйте необъявленные для экспорта декларации верхнего уровня.
- По умолчанию помещайте новую сущность в существующий домен, если она естественным образом ему соответствует.
- Сохраняйте согласованность имён файлов и каталогов с моделью `<domain>/<cluster>/<joint>/<family>`.

## Правила согласования изменений (обязательно)

- Если задача требует структуры, выходящей за пределы `<domain>/<cluster>/<joint>/<family>`, сначала сообщите об архитектурном конфликте и только затем предложите решение.
- Создавайте новый домен только тогда, когда сущность явно не относится ни к одному существующему домену.
- Создавайте новый кластер только через новую запись ADR (см. ADR-005; кластер `test` был добавлен через `adr/folder/cluster/002`).
- Создавайте новое звено только после достижения консенсуса на архитектурной сессии. Доменно-специфичные названия должны размещаться на уровне `family`, а не `joint`.

## Политика экспортов и агрегирующих файлов (обязательно)

- Корневые каталоги многодоменных библиотек имеют две генерируемые точки входа:
  - `src/lib/index.ts` использует фильтр доменов пакета, предоставляемый индексатором.
  - `src/lib/index.full.ts` использует полный фильтр для работы внутри рабочего пространства.
  Обе точки входа создаются из одного и того же проанализированного дерева. Отсутствующие или пустые домены пропускаются. `index.full.ts` — явно предусмотренное исключение из правила единственного `index.ts` в корне; он исключается из npm-пакета.
- Сохраняйте полные внутренние реализации публичных доменов и ресурсы времени выполнения внутри пакета, даже если соответствующий домен не экспортируется через публичную корневую точку входа: включённые компоненты могут от них зависеть.
- Приватные `geo`/`wbd`, сервер `sandbox`, stories, тесты и полная точка входа исключаются из npm.
- Не добавляйте вручную файлы реэкспорта или дополнительные промежуточные уровни реэкспорта.
- Не редактируйте вручную агрегирующие `index.ts`. Перегенерируйте их с помощью существующего механизма индексации.
- Если задача пользователя противоречит этим архитектурным правилам, явно сообщите о конфликте до начала работы.

## Координация нескольких агентов (обязательно)

Полный протокол координации нескольких агентов — журнал координации, мягкая блокировка доменов и роли — описан в `../lankatour.ru/AGENTS.md`.

Отчёты и заявки, связанные с библиотекой, инструментами, публикацией npm-пакетов и песочницей, записывайте в:

`../.docs/stylist-svelte/chat/<YYYYMMDD>/`

При необходимости создавайте каталог соответствующей даты. Выбирайте чат по проекту задачи, а не по текущему рабочему каталогу.

- Работы, относящиеся непосредственно к продукту сайта, бронированию, платежам и интеграциям, включая приватные компоненты `travel`, используемые LankaTour, записывайте в `../.docs/lankatour.ru/chat/<YYYYMMDD>/`.
- Для других проектов используйте `../.docs/<project>/chat/<YYYYMMDD>/`.
- Для межпроектных задач сохраняйте полную запись в чате основного проекта и краткую заметку со ссылкой в другом проекте.

Перед редактированием чего-либо в `stylist-svelte/src/lib/<domain>/**` объявите соответствующий домен в чате проекта и/или другим агентским сессиям.

Это дерево каталогов наиболее подвержено конфликтам параллельных изменений, поскольку агрегирующие файлы экспорта и манифест песочницы генерируются на основе всего дерева.

Агентам запрещено самостоятельно запускать CLI, описанные ниже в политиках генерации индексов и проверки ошибок.

Эти команды выполняет исключительно Дмитрий, поскольку они сканируют и перезаписывают всё дерево и могут конфликтовать с незавершёнными изменениями других агентов.

## Политика генерации индексов (обязательно)

Нативные инструменты индексации, DI reader, аудитор и средства анализа ошибок находятся в соседнем приватном репозитории:

`D:\2026\cloudflare\stylist-svelte-tools`

Они написаны на TypeScript и требуют Node.js версии 24.11 или выше.

- Скрипты сайта запускают аудитор через `scripts/auditor.mjs`, который запускает нативную индексацию и `scripts/reader.mjs pipeline`.
- Результаты отчётов сохраняются в `D:\2026\cloudflare\stylist`, включая `di\output`, `auditor\output` и `errors\output`.
- Команда `yarn stylist:index` запускает TypeScript-индексацию `scripts/indexation.mjs`. Её результат побайтово идентичен результату устаревшего Python-скрипта `stylist\indexation\cli.py`, который больше не используется.
- Копия в `D:\2026\projects\vibe-management.pro\packages\stylist` устарела. Не читайте и не редактируйте её.
- Изменения инструментов TypeScript фиксируйте коммитами в `stylist-svelte-tools`.

Не редактируйте вручную сгенерированные агрегирующие файлы `index.ts` и `index.full.ts`.

Файлы реализации отдельных сущностей с именем `index.ts` являются исходным кодом и могут изменяться в соответствии с правилами изменения исходников. Генератор сохраняет такие файлы.

### Когда требуется перегенерация индексов

После любых изменений, способных повлиять на экспорты или импорты в `stylist-svelte/src/lib/**`, необходимо перегенерировать агрегирующие файлы:

```
yarn stylist:index
```

Команда выполняется из `D:\2026\cloudflare\lankatour.ru` и запускает:

```
node "D:\2026\cloudflare\stylist-svelte-tools\scripts\indexation.mjs"
```

Новые, переименованные или перемещённые компоненты также требуют отдельной перегенерации манифеста песочницы. Иначе компоненты останутся невидимыми в песочнице, даже если успешно проходят проверку типов.

```
yarn stylist:manifest
```

Команда выполняется из того же каталога и запускает:

```
node "D:\2026\cloudflare\stylist-svelte-tools\scripts\auditor.mjs" --manifest-only
```

Не запускайте ни одну из этих команд самостоятельно. См. политику координации нескольких агентов выше. Сообщите Дмитрию, какие команды необходимы и почему.

- Считайте сгенерированные файлы `index.ts` источником истины.
- Если ошибки TypeScript выглядят связанными с устаревшими агрегирующими экспортами, сначала попросите Дмитрия перегенерировать индексы, а затем продолжайте исправления.

## Политика проверки ошибок (обязательно)

Вместо отдельного запуска двух анализаторов используется единый CLI:

```
yarn stylist:errors
```

Команда выполняется из `D:\2026\cloudflare\lankatour.ru` и запускает:

```
node "D:\2026\cloudflare\stylist-svelte-tools\scripts\errors.mjs"
```

Требуется Node.js версии 24.11 или выше.

Не запускайте эту команду самостоятельно. См. политику координации нескольких агентов выше.

Когда необходим свежий отчёт об ошибках, попросите Дмитрия выполнить команду. Учитывайте, что выполнение может быть продолжительным: рекомендуется предусматривать не менее 20 минут.

CLI последовательно запускает:

```
npx tsc --noEmit
```

в каталоге `stylist-svelte`, затем:

```
yarn check
```

в том же каталоге.

### Генерируемые результаты анализаторов

```

stylist\errors\yarn\yarn_check_stylist_svelte.json
```

### Сводный отчёт

```

```

Отчёт представляет собой заголовочный список файлов с ошибками, расположенных в каталоге:

```
stylist\errors\output\<timestamp>\**
```
