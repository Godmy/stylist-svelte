# src — исходники библиотеки и песочницы

`src` содержит корневые точки входа библиотеки, приложение SvelteKit и тесты.
Реализации доменов находятся в физических репозиториях `modules/`, согласно
[modules.json](../modules.json).

| Путь                               | Назначение                                      |
| ---------------------------------- | ----------------------------------------------- |
| [lib/](lib/readme.md)              | Генерируемые публичная и полная точки входа     |
| [routes/](routes/readme.md)        | Страница песочницы и серверные API              |
| [test/](test)                      | Тесты и harness-компоненты темы                 |
| [app.css](app.css)                 | Общие стили приложения                          |
| [app.html](app.html)               | HTML-шаблон SvelteKit                           |
| [hooks.server.ts](hooks.server.ts) | Запись серверных ошибок через DiagnosticManager |

SvelteKit и Vite используют физические алиасы из
[scripts/prepare-module-sources.mjs](../scripts/prepare-module-sources.mjs).
`$stylist/button/...` адресует `modules/interaction/button/...`; дополнительного
дерева исходников в `src/lib/button` нет.

Глобальная генерация точек входа, манифеста и отчётов ошибок выполняется Дмитрием
из родительского проекта. Правила редактирования и ограничения hot reload:
[AGENTS.md](../AGENTS.md).

Навигация по документации: [index.md](index.md). Устройство проекта:
[architecture.md](architecture.md). Проверенные изменения:
[changelog.md](changelog.md). Оставшиеся действия перед выпуском:
[backlog.md](backlog.md).

## Аналитическая оценка архитектуры

Раздел возвращает SWOT, риски и стратегии прежнего аудита `81bd28b90`, который
был сохранён в `681e886ea` до PR #4. Оценки обновлены с учётом P0-исправлений,
компактного манифеста и module-переноса. Это инженерная оценка, не новый полный
runtime-аудит. Точные release-препятствия и результаты проверок — в
[backlog.md](backlog.md); инвентарь — в [lib/readme.md](lib/readme.md).

### Сильные стороны

| Свойство                                            | Практическая ценность                                      | Ограничение                                                  |
| --------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------ |
| Детерминированная адресация и одна сущность в файле | Упрощает навигацию, ревью и работу агентов                 | Соблюдение правил нужно проверять по реализации              |
| Генерируемые barrel-файлы                           | Общий механизм экспорта и меньше ручных расхождений        | После изменения дерева нужна человеческая регенерация        |
| Направление data → … → component                    | Делает зависимости понятными и проверяемыми                | Само правило не доказывает отсутствие нарушений              |
| Recipe/slot/behavior/contract — DSIAP               | Интерфейс компонента доступен отдельно от Svelte-разметки  | Проекция манифеста не заменяет анализ импортов               |
| Широкий доменный набор                              | Общие UI-сущности, бизнес-наборы, графы и WebGL            | Охват следует отделять от качества и полноты                 |
| Песочница из собственных компонентов                | Регресс может проявиться в рабочем инструменте             | Это не автоматическая проверка каждой story                  |
| Ленивые stories и компактное tree                   | Поиск и навигация без сериализованного массива descriptors | Любой импортированный story-модуль может влиять на сборку    |
| Физические владельцы и приватный travel             | Истории сохраняются; продуктовая граница стала явной       | Синхронизация gitlinks и доступ участников остаются задачами |

### SWOT

SWOT — качественная авторская оценка. Размер инвентаря не используется как
доказательство зрелости; внешние возможности и угрозы — сценарии для обсуждения.

|                | Полезно                                                                                                                                                                                                                                                                                            | Риск                                                                                                                                                                                                                                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Внутреннее** | **S — Strengths**<br>Детерминированные адреса и barrel-генерация.<br>Широкая карта 51 домена и DSIAP-интерфейсы.<br>Собственная песочница и компактное дерево для инструментов.<br>Графы, presentation и WebGL как специализированные направления.<br>Разделение Git-владения и приватного travel. | **W — Weaknesses**<br>Незавершённая регенерация корней.<br>Полный CI и независимая упаковка не подтверждены.<br>Не установлено достаточное покрытие UI-сценариев.<br>Container-preview не проверяет все viewport-условия.<br>Кандидаты на дубли, нетипизированные stories и внешний процесс генерации.           |
| **Внешнее**    | **O — Opportunities**<br>MCP/RAG поверх дерева, recipe и исходников.<br>Скриншоты × устройства × темы и визуальное ревью.<br>Отдельные вертикальные наборы при наличии потребителей.<br>Переиспользование presentation/WebGL.<br>Понятная карта владельцев для участников.                         | **T — Threats**<br>Рост UI быстрее, чем его проверок.<br>Незаметные регрессии при массовых правках агентов.<br>Зависимость процесса от локального окружения владельца и доступа к репозиториям.<br>Несогласованные module-ревизии.<br>Разрыв между документацией исходников и поведением опубликованного пакета. |

### Сценарии развития

Сохранены четыре направления прежнего анализа. Вместо непроверенных сроков,
вероятностей и прогнозов объёма указаны условия и критерии результата.

| Сценарий                                  | Предпосылки                                                | Возможный результат                                       | Основной риск                                       |
| ----------------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------- | --------------------------------------------------- |
| A. Наращивание инвентаря                  | Новые компоненты без усиления проверки                     | Более широкий набор                                       | Рост сломанных stories и расхождения документации   |
| B. Стабилизация ядра                      | Закрыты P0, полезные тесты и визуальная проверка           | Воспроизводимый пакет и проверенные общие UI-сущности     | Зелёные fixtures принять за готовность всего набора |
| C. Система дизайна с инструментами для ИИ | Стабильное ядро, recipe-контекст, MCP и screenshot-цикл    | Ревью и улучшение компонентов через проверяемые артефакты | Автоматические правки без проверки человеком        |
| D. Платформа доменных наборов             | Подтверждённые потребители и стабильные package-boundaries | Переиспользование вертикалей отдельно от общего пакета    | Фрагментация API и усложнение совместимости         |

### Стратегии

1. Сопровождать рост инвентаря проверкой значимых сценариев, story и визуального результата.
2. Считать файловые владельцы источником реализации; манифест — генерируемым каталогом,
   а не доказательством зависимостей или работоспособности. Проверять согласованность.
3. Сохранять публичное ядро независимым от приватных вертикалей; module-разделение
   само по себе не означает отдельный npm-пакет для каждого владельца.
4. Проверять компоненты в контейнере и страницы в реальном viewport; iframe меняет
   размеры viewport, но не эмулирует touch, DPR и пользовательские предпочтения сам по себе.
5. Давать ИИ скриншот вместе с recipe, исходниками, аргументами и измерениями;
   после правки повторять capture и проверять результат.

### Историческая база сравнения

Сохранены значимые измерения первоначального аудита `81bd28b90`, чтобы
не терять основание прежних оценок. Это наблюдения автора в чистом клоне
без private geo/wbd; они не описывают сегодняшнюю ревизию и не заменяют
новый прогон. Старые build-замеры получены после временной подготовки клона.

| Область                          | Измерение прежнего аудита                                                                                        | Как интерпретировать теперь                                                  |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Инвентарь                        | 689 компонентных index.svelte и 658 stories на доступном диске; 779 descriptors и 744 story-признака в манифесте | Методики различались; новые таблицы считают все доступные физические домены  |
| Atomic Design в старом манифесте | atom 209, molecule 270, organism 276, template 20, page 4                                                        | Основание оценки «нижние уровни преобладают»; не свежий inventory            |
| Типизация stories                | 654 вхождения `: any` / `as any`, из них в 512 story-файлах                                                      | Исторический сигнал риска; текущие количества и семантику проверить отдельно |
| Unit-тесты                       | Один `*.test.ts` в theme                                                                                         | Это прежний узкий подсчёт, без нынешних Node fixtures и integration-набора   |
| Сборка песочницы                 | 3 мин 09 с; client 1:19, server 2:16; 1685 client JS-чанков                                                      | Замер старого графа, не доказательство текущей скорости или успешной сборки  |
| Build-выход                      | 22 МБ immutable assets; Cloudflare output 77 МБ / 8074 файла                                                     | Состав и размер после module-переноса повторно не измерены                   |
| Предупреждения сборки            | 73 state_referenced_locally, 42 css_unused_selector                                                              | Старые количества; актуальную диагностику получать на новой ревизии          |

### Что стало с первоначальными P0-замечаниями

| Замечание прежнего аудита                                        | Изменение в исходниках                                                              | Незавершённая проверка                                       |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Необъявленный Prettier-плагин и несовпадение ESLint-конфигурации | Конфигурация исправлена в afb625862                                                 | Полный lint по текущим владельцам                            |
| Отсутствующий graph dataset                                      | Dataset возвращён в static и загружается story через fetch                          | Успешная сборка и выполнение story                           |
| Публичный token импортирует private geo                          | Preset хранит публичные собственные значения                                        | Проверка package-boundary и потребителя без private checkout |
| Один корень экспортирует приватные сущности                      | Введены public/full entrypoints и фильтры                                           | После module-переноса требуется human regen                  |
| Package-files исключает зависимости экспортируемых сущностей     | Введены source preflight, assembly публичных реализаций и сохранение runtime-assets | Установка tarball, root/subpath imports и CSS                |
| Не учтены CSS side effects                                       | package.json сохраняет CSS как side-effectful                                       | Проверить стили в приложении-потребителе                     |

Таким образом, прежние критические оценки остаются объяснением приоритетов,
а выполненные исправления не возвращаются в список открытых дефектов.
